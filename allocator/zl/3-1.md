### 3. **动态扩展机制(3.3.3)**

#### 水位监控策略
- **配置参数**：LOW_WATER_NODES、EXPAND_PAGES
- **检查时机**：每次alloc_pages前
- **触发逻辑**：`free_nodes < LOW_WATER → 扩展`

#### 扩展执行流程（6步详解）
```
1. 检测低水位
2. 选择扩展来源zone(遍历所有zone)
3. 分配内存页(zone.alloc_pages)
4. 将内存页添加到节点池
   4.1 划分扩展区域
   4.2 添加到free_head链表头
   4.3 更新计数
5. 记录日志
6. 扩展完成,继续原分配请求
```

#### 扩展失败处理
- 失败场景：所有zone无法分配、内存严重不足
- 处理策略：记录警告 → 尝试用现有节点继续 → 最终失败返回NoMemory → 优雅降级不崩溃

### 4. **高效节点管理(3.3.4)**

#### alloc_node实现（带注释代码）
```rust
pub fn alloc_node(&mut self) -> Option<usize> {
    // 1. 检查空闲链表
    let node_addr = self.free_head?;
    // 2. 从链表头部取出节点
    let node = unsafe { &mut *(node_addr as *mut ListNode) };
    self.free_head = node.next;
    node.next = None;
    // 3. 更新统计
    self.total_allocations += 1;
    self.free_nodes -= 1;
    // 4. 返回节点地址
    Some(node_addr)
}
```
- **性能特性**：O(1)、无内存分配、缓存友好

#### dealloc_node实现
```rust
pub fn dealloc_node(&mut self, node_idx: usize) {
    // 1. 清空节点数据
    unsafe { core::ptr::write(...) };
    // 2. 更新链表头
    self.free_head = Some(node_idx);
    // 3. 更新统计
    self.total_deallocations += 1;
    self.free_nodes += 1;
}
```
- **性能特性**：O(1)、插入链表头部、清零防信息泄漏

#### get_node访问接口
- 只读访问：`get_node`
- 可变访问：`get_node_mut`
- 用途：free list遍历、节点数据读写、链表指针修改

#### 统一节点管理接口图
```
所有zone、所有order的free list操作统一通过GlobalNodePool:

PooledLinkedList (每个order一个):
  ├─ insert_sorted(pool, data) 
  │    └→ pool.alloc_node()  // 统一分配
  ├─ pop_front(pool)
  │    └→ pool.dealloc_node(idx)  // 统一释放
  └─ remove(pool, idx)
       └→ pool.dealloc_node(idx)  // 统一释放
```

### 5. **与BuddySet的协同机制(3.3.5)**

#### PooledLinkedList结构
```rust
pub struct PooledLinkedList {
    head: Option<usize>,
    tail: Option<usize>,
    len: usize,
}
```
- **轻量设计**：只存head/tail/len，不存实际节点
- 实际节点存储在GlobalNodePool中

#### 有序插入(insert_sorted)实现
- 5步流程：分配节点 → 找插入位置(按addr升序) → 初始化节点 → 更新链表指针 → 更新tail/len
- **有序性保证**：free list按地址升序，便于buddy合并和split操作

#### 查找与删除优化
- `find_by_addr`: O(n)查找，返回`(node_idx, prev_idx)`
- `remove_with_prev`: O(1)删除，利用已知prev_idx
- **优化策略**：查找和删除分离，避免二次遍历，buddy合并时先find再remove，复用prev_idx实现O(1)删除
