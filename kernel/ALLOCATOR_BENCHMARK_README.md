# Axvisor Allocator Comprehensive Benchmark

这是一个完整的内存分配器测试套件，集成在 `kernel` 模块中，在系统启动后自动运行。

## 测试内容

### 1. 基础功能测试 (`basic_tests`)
- **小对象分配测试**：8B - 2KB 大小，每种大小 100 次分配
- **大对象分配测试**：4KB - 4MB 大小
- **地址对齐验证**：8 - 16384 对齐要求，每种 50 次分配
- **读写完整性验证**：8KB 内存读写模式测试
- **分配释放循环**：5000 轮，每轮多种大小分配释放

### 2. 性能测试 (`performance_tests`)
- **吞吐量测试**：100,000 次连续分配/释放
  - 统计平均延迟、最小/最大延迟
  - 计算 M ops/s 吞吐量
- **延迟分布测试**：10,000 次操作，计算 P50/P90/P99 延迟
- **混合模式测试**：模拟真实场景大小分布
  - 小对象 30%，中对象 40%，大对象 30%

### 3. 压力测试 (`stress_tests`)
- **内存耗尽测试**：
  - 持续分配 1MB 块直到内存不足
  - 统计最大可分配内存
- **碎片化测试**：
  - 三阶段：分配 2000 个对象 → 碎片化释放 → 再分配 500 个
  - 验证碎片化后性能
- **边界条件测试**：
  - 0 字节分配
  - 超大对齐（16KB, 64KB, 256KB, 1MB）
  - 非 2 的幂次大小

### 4. 多核多线程测试 (`multithread_tests`)
- **并发分配测试**：
  - 使用所有 CPU 核心
  - 每个线程 5000 次分配/释放
  - 验证无数据竞争
  - 测试并发吞吐量
- **并发竞争测试**：
  - 所有线程同时分配相同大小（64B）
  - 测试锁竞争性能
  - 统计高竞争下吞吐量
- **长时并发测试**：
  - 多线程持续运行 30 秒
  - 验证长时间稳定性

### 5. 内存泄漏检测 (`leak_detection`)
- **分配释放平衡测试**：
  - 10 轮测试，每轮 5000 次操作
  - 每轮后验证分配数等于释放数
- **重复测试循环**：
  - 5 个完整测试周期
  - 每个周期后验证无累积泄漏

## 统计指标

### 计数统计
- `total_allocations`：总分配次数
- `total_deallocations`：总释放次数
- `leaked_allocations`：泄漏次数（分配 - 释放）

### 大小分类统计
- `small_allocs`：小对象 (<4KB)
- `medium_allocs`：中对象 (4KB - 1MB)
- `large_allocs`：大对象 (>1MB)

### 性能统计
- `avg_alloc_latency`：平均分配延迟
- `min_alloc_time_ns`：最小分配时间
- `max_alloc_time_ns`：最大分配时间
- `throughput`：吞吐量（ops/s）

### 内存使用统计
- `peak_allocated_bytes`：峰值分配内存
- `current_allocated_bytes`：当前分配内存

## 运行方式

测试在系统启动后自动运行，无需额外配置。启动 axvisor 后，测试将自动执行并输出详细报告。

## 设计特点

1. **全面覆盖**：从基础功能到极端压力场景
2. **性能导向**：量化延迟、吞吐量、内存使用
3. **多线程支持**：利用所有 CPU 核心
4. **泄漏检测**：自动跟踪分配/释放平衡
5. **实时统计**：使用原子操作保证线程安全
6. **详细报告**：完整的测试报告输出

## 预期性能

在 4 核心、512MB 内存的系统上，预期性能：

- **吞吐量**：1-5 M ops/s（取决于对象大小）
- **延迟**：100-500 ns（小对象分配）
- **并发扩展性**：吞吐量随核心数近似线性增长
- **内存使用**：峰值不超过总内存的 80%

## 故障排查

如果测试失败或性能异常，检查：

1. **内存配置**：确保 axvisor 有足够的内存配置
2. **CPU 核心数**：多线程测试需要 SMP 支持
3. **分配器配置**：确认 buddy-slab-allocator 正确初始化
4. **日志级别**：使用 `log-level-*` feature 查看详细输出
